四、两种写法对照 同一套流程，两种组织方式

Promise 链式写法 .then()
// 延时工具：返回 Promise
function yuan_sleep(ms) {
  return new Promise(function (resolve) {
    setTimeout(resolve, ms);
  });
}

function yuan_runPromise() {
  yuan_sleep(2000)                      // 买原料
    .then(function () {
      // 和面 + 和馅 同时开始，都完成才继续
      return Promise.all([
        yuan_sleep(1500),               // 和面
        yuan_sleep(2000)                // 和馅
      ]);
    })
    .then(function () {
      return yuan_sleep(2000);        // 包饺子
    })
    .then(function () {
      return yuan_sleep(1500);        // 吃饺子
    })
    .then(function () {
      console.log('吃完了！');
    })
    .catch(function (err) {
      console.error('哪一步出错了：' + err.message);
    });
}
async / await 写法 同步的书写感
// 同一个 yuan_sleep，写法更直观
async function yuan_runAsync() {
  try {
    await yuan_sleep(2000);            // 买原料

    // 同时进行：把两个 Promise 一起 await
    await Promise.all([
      yuan_sleep(1500),              // 和面
      yuan_sleep(2000)               // 和馅
    ]);

    await yuan_sleep(2000);            // 包饺子
    await yuan_sleep(1500);            // 吃饺子

    console.log('吃完了！');
  } catch (err) {
    console.error('哪一步出错了：' + err.message);
  }
}

五、为什么要这样写 三个关键点

1. Promise 就是"欠条" 调用异步操作立刻拿到一个 Promise（欠条），它有三种状态：pending 等待、fulfilled 成功、rejected 失败。成功用 .then()，失败用 .catch()。
2. Promise.all 才是"同时" 和面、和馅互不依赖，放进 Promise.all([...]) 一起启动，总耗时取两者中较长的 2.0 秒；如果串行 await，就要 1.5 + 2.0 = 3.5 秒。
3. async/await 是 Promise 的语法糖 await 只是"等这个 Promise 有结果"，代码看起来像同步，本质仍是异步；async 函数的返回值自动被包成 Promise，所以能用 .then() 接。
4. 顺序依赖不能并行 包饺子必须等面、馅都好；买原料必须最先。只有互不依赖的任务才能并行，这是排查性能问题的第一课。
5. 一定要 try...catch async 函数里 Promise 被 reject 会变成异常抛出；漏了 try...catch 就会变成"未处理的 Promise 拒绝"，流程中断还看不到原因。
6. 别忘 await 写了 yuan_sleep(2000) 却忘了 await，后面的步骤会立刻执行 —— 饺子还没包就开始吃了。

六、串行 vs 并行 耗时对照

做法 耗时 说明
串行 await 和面 + 和馅 1.5 + 2.0 = 3.5 s 和完面再去和馅，白白多等 1.5 秒
Promise.all 并行 max(1.5, 2.0) = 2.0 s 两个动作同时开始，等最慢的那个，本页采用
整锅饺子总耗时 2.0 + 2.0 + 2.0 + 1.5 = 7.5 s 买原料 → 并行和面馅 → 包 → 吃
