// 1) async / await 写法（推荐，本页实际使用） async function yuan_loadUsers() { try { const yuan_res = await fetch('https://jsonplaceholder.typicode.com/users'); // 注意：fetch 只在网络失败时 reject，404 / 500 不会，要自己检查 ok if (!yuan_res.ok) { throw new Error('HTTP ' + yuan_res.status); } const yuan_users = await yuan_res.json(); // 文本 → JS 数组 yuan_render(yuan_users); // 渲染卡片 } catch (yuan_err) { console.error('请求失败：', yuan_err.message); } } // 2) Promise 链式写法，效果完全一样 fetch('https://jsonplaceholder.typicode.com/users') .then(function (res) { if (!res.ok) { throw new Error('HTTP ' + res.status); } return res.json(); }) .then(function (users) { console.log(users.length); // 10 }) .catch(function (err) { console.error(err.message); });

五、跨域那点事 为什么有的接口能拿，有的被拦

同源策略

浏览器规定：协议、域名、端口三者完全相同才算"同源"。本页来自本地文件，而接口在 jsonplaceholder.typicode.com，属于跨域请求。

CORS 是服务器的"通行证"

接口在响应头里写上 Access-Control-Allow-Origin: *，浏览器才肯把数据交给 JS。这是服务器的事，前端改不了。

预检请求 OPTIONS

带自定义头或 application/json 的 POST 会先发一个 OPTIONS 预检，服务器同意后才会发真正的请求。

fetch 的两个坑

① HTTP 404 / 500 不会触发 catch，必须判断 response.ok；② 默认不携带 Cookie，需要时加 credentials: 'include'。

拿到的是文本不是对象

await res.json() 才是把响应体按 JSON 解析成数组 / 对象；await res.text() 则拿到原始字符串（见第三节）。

跨域不等于后端不能要

浏览器拦，服务器/抓包工具不拦。真实项目中也可用同源代理（Nginx、Vite proxy）绕过浏览器限制。
