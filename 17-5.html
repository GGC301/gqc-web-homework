JavaScript 的两种定时器

setTimeout：等一会儿，只做一次；setInterval：每隔一会儿，反复地做。它们都在"时间到了"才执行，不阻塞后面的代码。

一、先认识这两位 一次性 vs 周期性

setTimeout(函数, 毫秒)

一次性定时器 —— 像"闹钟"，响一次就完事

语法
var id = setTimeout(fn, 1000);
取消
clearTimeout(id);
返回
数字 id（从 1 开始自增），取消时要用它
典型场景
延迟提示、动画延时、防抖、模拟网络延时

setInterval(函数, 毫秒)

周期性定时器 —— 像"心跳"，不停地重复

语法
var id = setInterval(fn, 1000);
取消
clearInterval(id);
返回
数字 id，不清理就会一直跑下去
典型场景
时钟、秒表、轮播图、进度条、倒计时

六、必须知道的几点 定时器不是"精确的闹钟"

1. JS 是单线程的 定时器只负责"排队"，如果主线程正忙（长循环、大计算），回调就得等，实际时间只会更晚，不会更早。
2. setTimeout(fn, 0) 不是立刻执行 它表示"尽快"，实际最小延迟约 4 毫秒，并且要等当前同步代码跑完。
3. setInterval 会漂移、会堆积 回调如果耗时超过间隔，下一次会排队。要求准时就用 setTimeout 递归 + 时间差校正。
4. 后台标签页会被节流 页面切到后台时，浏览器会把定时器最小间隔拉长到 1 秒甚至更多，所以别用它在后台做精确计时。
5. 用完一定要 clear clearInterval 忘写，定时器会一直跑、越积越多，导致页面卡顿。单页应用里还要在组件销毁时清理。
6. 定时器 id 是数字 同一个页面里 id 是全局自增的，不要自己随便造一个数字传给 clear，那样清不掉真正的定时器。
7. 回调里的 this 是 window 普通回调里 this 不再指向原对象；用箭头函数或提前 var that = this 保存。
8. 定时器不是异步 I/O 它只是把回调丢进"宏任务队列"，和网络请求、事件回调一起排队，谁先到点谁先执行。

七、两种定时器对照表

对比项 setTimeout setInterval
执行次数只执行一次每隔一段时间执行，直到被清除
取消方法clearTimeout(id)clearInterval(id)
像什么闹钟（响一次）心跳（一直跳）
是否阻塞不阻塞，后面的代码先执行不阻塞
常见用途延迟提示、模拟请求耗时、防抖节流时钟、秒表、轮播、进度条
精确度受主线程繁忙影响受主线程影响，且可能产生漂移
互相实现setTimeout 递归可以模拟 setInterval；setInterval 也能用计数模拟 setTimeout

八、本页用到的核心代码

/* ---------- 1. setTimeout：延迟执行，可取消 ---------- */ var yuan_timer = setTimeout(function () { console.log('3 秒后才执行'); }, 3000); clearTimeout(yuan_timer); // 反悔了，取消掉 /* ---------- 2. setInterval：周期执行，必须清理 ---------- */ var yuan_sec = 0; var yuan_interval = setInterval(function () { yuan_sec++; console.log('已过去 ' + yuan_sec + ' 秒'); }, 1000); clearInterval(yuan_interval); // 停下，否则永远在跑 /* ---------- 3. 用 setTimeout 递归代替 setInterval ---------- */ function yuan_tick() { console.log(new Date().toLocaleTimeString()); setTimeout(yuan_tick, 1000); // 每次只安排下一次 } yuan_tick(); /* ---------- 4. 最常见的用法：包一个延时 Promise ---------- */ function yuan_sleep(ms) { return new Promise(function (resolve) { setTimeout(resolve, ms); // 17-6.html 的包饺子就靠它 }); }
