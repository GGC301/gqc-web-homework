一、五层结构一览 从渠道到知识底座

用户层

App、小程序、H5、企业微信、电话与工单，多渠道统一接入同一套问答能力。

在线链路

会话网关 → 语义理解 → 知识检索 → 答案生成 → 回复/转人工，是用户能感知到的响应过程。

知识库

文档接入、清洗、切片、向量化、索引构建，落到向量库、倒排索引、知识图谱与版本管理。

模型层

大模型、Embedding、Rerank，加上规则兜底与缓存队列，决定回答质量与响应成本。

科研方向

数据集与标注、离线评测、在线 A/B、误差与可解释性，构成可复现的实验闭环。

二、一次提问是怎么被回答的 RAG 的完整链路

  1. 用户在多渠道发起提问，会话网关 建立长连接，带上会话 ID 与身份信息，做鉴权与限流。
  2. 语义理解 做意图分类、实体抽取与多轮状态追踪，判断该走知识问答还是转人工。
  3. 知识检索 把问题向量化后做 ANN 召回，同时用 BM25 做关键词召回，两路结果融合后由 Rerank 精排。
  4. 答案生成 把 Top-K 片段、对话历史与系统提示词拼装进 Prompt，由大模型生成带引用的答案。
  5. 校验与兜底：置信度低于阈值、命中敏感词或问题超出知识范围时拒答并转人工，避免编造。
  6. 回流沉淀：会话日志、点击与转人工行为进入数据集，驱动知识更新与模型迭代。

三、科研方向可以做什么 ★ 标注的模块

检索增强生成（RAG）

研究切片粒度、混合检索权重、重排序模型与上下文压缩对答案质量的影响，常用指标 Recall@K、MRR、nDCG。

对话理解

小样本意图识别、多轮指代消解、槽位填充与状态追踪，指标看 F1 与意图混淆矩阵。

可信回答

事实一致性、引用溯源、幻觉检测与拒答策略，是智能客服能否真正落地的关键问题。

评测与实验

离线基准 + 在线 A/B 双轨评测，配合统计显著性检验与误差归因，保证实验结论可复现。
