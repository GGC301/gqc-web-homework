一、五个层次，各管一段 从上到下的请求路径

用户层

PC 商城、移动 H5、微信小程序、原生 App。同一套后端，四种触点，负责流量入口与交互体验。

接入层

CDN 静态加速、Nginx 负载均衡、API 网关、统一鉴权。做 TLS 卸载、限流、路由与身份校验。

业务服务层

商品、搜索、购物车、用户、订单、支付、库存、营销八个微服务，各自独立部署、独立扩容。

中间件层

Redis 缓存、Kafka 消息队列、Elasticsearch 检索、分布式任务调度，负责性能、解耦与补偿。

数据层

MySQL 主从集群、对象存储 OSS、数据仓库、日志监控，是订单、商品与行为数据的最终归宿。

二、一次"下单"是怎么走完的 把架构图串成一条线

  1. 用户在 小程序 / H5 点击"提交订单"，请求先打到 CDN 拿静态资源，业务请求直达 Nginx。
  2. Nginx 把请求转给 API 网关，网关校验 JWT 令牌、限流、按灰度规则路由到订单服务。
  3. 订单服务 先调用 库存服务 预占库存、营销服务 计算优惠，写入订单表（状态：待支付）。
  4. 下单成功消息投递到 Kafka，异步通知积分、推荐、通知等下游，主链路快速返回。
  5. 用户打开 支付服务 收银台，支付回调进来后置为已支付，再发消息驱动发货与对账。
  6. 所有关键数据落到 MySQL，图片落 OSS，日志进日志中心，报表与推荐从数据仓库取数。

三、这张图是"画"出来的 Canvas 绘图的几个关键点

  1. 圆角矩形：roundRect 在旧浏览器里没有，用 arcTo 自己写一个，四段圆弧拼成方块。
  2. 高清适配：按 devicePixelRatio 放大画布，再 setTransform 缩放回来，文字才不会发虚。
  3. 坐标映射：以 1200×860 的设计坐标作图，按容器宽度整体缩放，图就是响应式的。
  4. 命中检测：把鼠标坐标除以缩放比还原成设计坐标，再遍历方块数组判断点在哪个矩形里。
  5. 导出图片：canvas.toDataURL('image/png') 直接拿到像素数据，挂到 a[download] 上就能保存。

四、核心代码 骨架部分

/* ---------- 1. 手写圆角矩形 ---------- */ function roundRect(x, y, w, h, r) { ctx.beginPath(); ctx.moveTo(x + r, y); ctx.arcTo(x + w, y, x + w, y + h, r); ctx.arcTo(x + w, y + h, x, y + h, r); ctx.arcTo(x, y + h, x, y, r); ctx.arcTo(x, y, x + w, y, r); ctx.closePath(); } /* ---------- 2. 设计坐标 → 屏幕坐标 ---------- */ var scale = cssWidth / 1200; // 1200 是设计稿宽度 canvas.width = cssWidth * dpr; canvas.height = cssHeight * dpr; ctx.setTransform(dpr * scale, 0, 0, dpr * scale, 0, 0); // 之后所有 fillRect / fillText 都用设计坐标 /* ---------- 3. 方块与命中检测 ---------- */ boxes.forEach(function (b) { roundRect(b.x, b.y, b.w, b.h, 10); ctx.fillStyle = rgba(b.color, .16); ctx.fill(); ctx.strokeStyle = rgba(b.color, .5); ctx.stroke(); ctx.fillText(b.title, b.x + 16, b.y + b.h / 2 - 9); }); function hit(x, y) { return boxes.find(function (b) { return x >= b.x && x <= b.x + b.w && y >= b.y && y <= b.y + b.h; }); } /* ---------- 4. 导出 PNG ---------- */ var a = document.createElement('a'); a.download = '电商全站系统架构图.png'; a.href = canvas.toDataURL('image/png'); a.click();
